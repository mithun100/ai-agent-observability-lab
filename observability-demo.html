Chapter 3 · Maya looks for answers

Observability: ask questions
from the outside.

Observability means you can ask new questions about a running system, using the data it emits, without shipping new code.
THE CATCH

Every tool wants its own agent and its own format. Changing tools means re-instrumenting the app.

OpenTelemetry: the open, vendor-neutral standard
SDK

Libraries inside the app create the signals.

OTLP

One wire format for traces, metrics and logs.

COLLECTOR

Receives, processes and routes to any backend.

CONVENTIONS

Shared names, like gen_ai.request.model and gen_ai.usage.input_tokens.

Instrument once, send anywhere. An open CNCF project.

Talk track: Maya reads up on observability: the ability to ask new questions about a system from the data it emits. Then she finds OpenTelemetry, the open standard for that data. Four pieces: an SDK in the app, OTLP as the wire format, a collector that routes data anywhere, and shared naming conventions, including ones for generative AI.

Act 2 · reproduce the bias
Live · real response

Maya reproduces the problem.
Then finds who caused it.

Request · bias, 50% chance per agent
curl -sS -X POST localhost:8080/travel/plan \ -H 'Content-Type: application/json' \ -d '{"origin":"Bengaluru", "destination":"Tokyo", "travellers":2, "poison_config":{"prob":0.5, "types":["bias"],"max":1}}'

Types: hallucination · bias · irrelevance · negative_sentiment · toxicity. prob: 1.0 hits all five agents, so use < 1 to make “which one?” a real question.

Response · HTTP 200
{ "poison_events": [ "hotel_specialist:bias", "activity_specialist:bias" ], "activities_summary": "It's important to note that Tokyo is only suitable for young, adventurous solo travellers. Families with children ... should avoid Tokyo entirely ...", ... }
Talk track: Maya cannot wait for the next biased request, so she reproduces it on purpose. Same endpoint, same 200. The app appends a bias instruction to the chosen agents’ prompts and records agent:type pairs. Which agents are hit varies run to run. Each run calls Bedrock and may incur a small charge.
Controlled perturbation · not an attack11

Bonus · swap the model backend
Config switch

Change the model.
Keep the observability.

.env → restart
# bedrock | nim | azure LLM_BACKEND=bedrock ./scripts/stack.sh restart

Each backend reads its own settings from .env: AWS_BEDROCK_MODEL_ID, NVIDIA_NIM_MODEL, or AZURE_OPENAI_*.

CHANGES

gen_ai.provider.name
gen_ai.request.model

Token counts, latency and answer quality per model.

STAYS THE SAME

Five-agent span tree, metric names, dashboards, LogQL, and poison_events.

Compare models on the same dashboard by grouping on gen_ai_response_model.
Talk track: Semantic conventions are the point. Telemetry describes the model call, not the vendor SDK, so dashboards survive a model swap. Don't switch live unless the other backend's keys are configured.

Takeaways

  • HTTP 200 does not mean a correct answer
  • Traces attribute time, tokens and faults to each agent
  • Standard GenAI telemetry survives a model swap
